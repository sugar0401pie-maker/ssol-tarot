# 개발 요청: 비슷한 예시 찾기를 의미 검색(임베딩)으로 바꾸기 (쏠 타로 v2.3.9)

## 왜
- 지금은 글자 2~4개 묶음을 비교해서 비슷한 고민 예시를 찾아요(`03_코드/retrieve.js`). 글자가 다르면 뜻이 같아도 못 찾아요(예: "남친이 결혼하자는데" ↔ "결혼 이야기가 나왔어요").
- 현재 성능(실제 고민 956건, 5겹 교차 검증, `eval/v239_eval.txt`): 점수표 1위 70.6% · 세부 고민 1위 49.9% · 세부 후보 8개 안 82.3%.
- 고민 틀 AI(A2 v4.10)는 이 후보 8개를 보고 세부 고민을 고르므로, **후보 안에 정답이 들어오는 비율(지금 82%)이 사실상 상한**이에요. 의미 검색으로 이 비율을 90% 이상으로 올리는 게 목표예요.

## 무엇을
1. 색인: `08_판별DB/data/frame_gold_v2.4.jsonl` 전 줄(약 4,300)의 `text`를 `normalize.js`로 정리한 뒤 임베딩 → 배포 때 한 번 만들어 저장.
2. 질문: 사용자 고민을 같은 방식으로 정리 → 임베딩 → 코사인 상위 20개.
3. 하이브리드: `0.7 × 임베딩 + 0.3 × 글자 검색` 점수(예시 코드 `03_코드/embedRetriever.example.mjs`, `setRetriever`로 끼움).
4. 결과 20개 → `subCandidates(neighbors, 8)` → `subPromptBlock(candidates, worry_subtopics)` → A2 v4.10의 `{SUB_BLOCK}`에 넣기. 점수표 두 번째 의견(`voteTable`)은 상위 5개로 그대로.
5. 같은 5겹 교차 검증으로 재고, 아래 표를 채워 주세요.

| 지표 | 글자 검색(지금) | 임베딩 | 하이브리드 |
|---|---|---|---|
| 점수표 1위 | 70.6% | | |
| 세부 고민 후보 8개 안 | 82.3% | | |
| 세부 고민 1위 | 49.9% | | |

## 참고
- 임베딩 모델은 운영에서 쓰는 것으로(한국어 지원). 색인은 고정이라 한 번만 만들면 되고, 질문은 한 번에 수십 토큰이라 비용·지연이 작아요.
- 원문은 저장하지 않아요: 색인은 익명화·합성 문장뿐이고, 질문 임베딩은 저장하지 말고 바로 버려 주세요.
- 하이브리드 비율(0.7/0.3)은 재 보고 바꿔도 돼요.
