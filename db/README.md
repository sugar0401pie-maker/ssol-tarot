# 07_DB — 미리 써 두는 문장 DB (검수용 엑셀)

결과 리포트에 들어가는 고정 문장 **1,894개**(v3.2)를 시트 11개로 나눠 둔 엑셀입니다. 상담사는 이 파일만 검수하면 되고, 개발은 스크립트 한 번으로 `tarot_data.json`에 반영합니다.

| 파일 | 용도 |
|---|---|
| `쏠타로_문장DB.xlsx` | 검수용 엑셀. 첫 시트 '읽어주세요'에 쓰는 법·색 범례·작성 예시·진행 현황(자동 계산) |
| `export_db.py` | `tarot_data.json` → 엑셀 다시 만들기 |
| `import_db.py` | 검수 끝난 엑셀 → `tarot_data.json` 반영 + `import_report.md`(바뀐 문장·경고) |
| `review_log.json` | 2026-10-07 문장 점검 결과(고친 것·제안·판단 필요). `export_db.py`에 세 번째 인자로 주면 '점검이력' 시트와 검수 메모가 채워짐 |
| `db_schema.py` | 시트 구성, ID 규칙, 검수 규칙(금지 표현·자리표시자·다가가기 표현) |

## 반영 방법

```bash
cd 07_DB
python3 export_db.py ../02_데이터/tarot_data.json 쏠타로_문장DB.xlsx review_log.json   # 엑셀 다시 만들기(점검이력 포함)
python3 import_db.py 쏠타로_문장DB.xlsx ../02_데이터/tarot_data.json --dry-run            # 미리보기(파일 안 바뀜)
python3 import_db.py 쏠타로_문장DB.xlsx ../02_데이터/tarot_data.json --only-confirmed     # 상태 '확정'만 반영
cd ../03_코드 && node test_tarot.mjs && node demo_pipeline.mjs                        # 반영 후 확인
```

- 최종 문장 = 수정안(있으면) 또는 현재 문장. 금지 표현이 들어가거나 `{name}` 같은 자리표시자가 빠진 수정안은 **반영하지 않고** 보고서에 남깁니다.
- 상태 '삭제'는 자동 반영하지 않습니다(목록 구조가 바뀌므로 개발에서 함께 수정).
- 반영 후에는 엑셀이 문장의 원본입니다. `build/` 의 초안 생성 스크립트를 다시 돌리면 초안으로 덮어쓰니 쓰지 마세요. 다음 검수 회차는 `export_db.py`로 엑셀을 새로 뽑아 시작합니다.
- 고민 맞춤 문장(연결 한 줄·맞춤 질문·이야기·내 고민에 대어 보면)은 AI가 쓰므로 DB에 없습니다.

## 점검이력 시트 (v2.4)

문장 890개를 한 줄씩 다시 읽고 고친 내역입니다. 각 행의 '검수 메모'에도 `[Claude 점검 · 고침/제안/판단 필요]`로 남아 있어요. 고친 문장은 이미 '현재 문장'에 반영돼 있고, '제안'은 직접 정해 주신 화면 문구라 그대로 두고 제안만 적었습니다.

## 안전키워드 시트 (v2.5)

- 한 칸에 단어를 쉼표로 적어요. 띄어쓰기 없이 적으면 되고(검사할 때 고민 원문의 띄어쓰기도 지워서 찾음), '위험 · 띄어쓰기 그대로'에 있는 두 글자 단어(자살·자해)만 원문 그대로 찾아요.
- '오탐 예외'에 적은 표현은 고민에서 지운 뒤 검사해요. 예: '혼자 살기'가 '자살'로 잡히는 문제 같은 걸 운영하며 모아 넣으면 됩니다. 단, 위험 신호를 놓칠 수 있으니 예외는 상담사 확인 후에만.
- 키워드는 보조 장치예요. AI 판단과 합쳐 더 높은 쪽을 따릅니다.
