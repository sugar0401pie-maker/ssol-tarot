# 판별 기준 고침 — CSO 검수 반영 (v2.3.22 · 2026-11-15)

CSO가 실제 고민 표본 100건 중 서비스와 정답 라벨의 결과 틀이 다른 글을 문장마다 판정했고, 그 판정 이유를 판별 기준에 넣었어요.

- 프롬프트: `08_판별DB/A2_고민틀_프롬프트_v4.14.txt` (v4.13에 기준 6개 추가, 규칙 1개 바꿈)
- 세부 정의: `02_데이터/worry_subtopics.json` v5 (30개 세부, 51곳)
- 채점: `08_판별DB/data/sub_equivalents.json`, `08_판별DB/subEquiv.mjs`
- 고친 곳 전체: `07_DB/쏠타로_v2.3.22_판별기준_검수표.xlsx`(+json)

## 1. 프롬프트 v4.14에 넣은 기준

| # | 기준 | 예 |
|---|---|---|
| 1 | 묻는 꼴이 먼저 | "언제쯤"이면 시기 세부, "~와 ~ 중"이면 고르기 세부 |
| 2 | 낱말 하나로 정하지 않음 | "대학원"이 있어도 면접을 앞둔 글이면 면접 세부 |
| 3 | 이미 일어난 일이 먼저 | 이미 그만뒀으면 퇴사 세부가 아님. 정했다는 말이 없으면 정한 것으로 읽지 않음 |
| 4 | 적어 둔 사정보다 실제로 바라는 것 | 사정을 말해도 이어지길 바라는지, 스스로를 의심하는지를 봄 |
| 5 | UF-ALL은 마지막에만 | 두 가지면 먼저 쓴 쪽, 같은 영역이면 그 영역 세부 |
| 6 | 카드로 답할 수 없는 질문은 답할 수 있는 질문으로 | 낼 돈을 피할 길 → 조만간 돈이 생길지 |

**바꾼 규칙:** v4.12의 "취업 면접만 JB-INTERVIEW, 입시·대학원 면접은 시험 쪽"을 "면접을 앞두고 붙을지를 물으면 대학원 면접도 JB-INTERVIEW"로 바꿨어요(CSO 판정). 대학 입시 면접은 그대로 시험 쪽이에요.

## 2. 세부 정의에서 크게 바뀐 것

| 세부 | 바뀐 점 |
|---|---|
| WK-WHEN | 떠나기로 정했다는 말이 분명할 때만. "그만둘까·그만둬도 괜찮을까"는 WK-QUIT |
| LV-LONGSOLO | 오래 혼자였다는 말이 있을 때만. "언제쯤"이면 LV-WHEN, 기간 말 없는 자기 의심은 LV-ABLE |
| ED-SCHOOL / EX2-GRAD | 대학원 연구·지도교수는 EX2-GRAD. 졸업 작품·졸업 요건은 ED-SCHOOL |
| MN-WHEN | "조만간 돈이 생길지·들어올지"를 포함. "언제"가 붙으면 급하다는 말이 있어도 이 세부 |
| PT-TWO | 셋 이상 적고 고르는 것도 포함. 비교하는 꼴이면 영역 낱말이 있어도 이 세부 |
| JB-WHEN / JB-WAIT | "언제쯤"이면 JB-WHEN. 이미 지원·면접을 마쳤으면 시기 말이 있어도 JB-WAIT |
| CR-CHANCE / CR-DEFINE | "정식으로 만나 봐도 될지"는 CR-CHANCE |
| UF-ALL | 세 가지 이상을 같은 무게로 물을 때만 |

## 3. 채점 — 같은 값으로 치는 짝 10개

CSO가 "둘 다 됨"으로 판정한 짝은 어느 쪽이 나와도 정답으로 쳐요. 판별은 바꾸지 않고 채점에만 써요.

CR-WAIT/CR-SIGNAL · JB-WAIT/JB-APPLY · JB-WHERE/PT-WHAT · JB-RETURN/JB-WHEN · RL-CONTACT/RL-TRUE · EX2-LONG/EX2-WAIT · CR-CHANCE/CR-MIND · CR-DISTANCE/CR-CHANCE · CR-DEFINE/CR-MIND · MR-WHETHER/MR-THIS

```js
import { sameSub } from "./subEquiv.mjs";
sameSub(gold, got) // 같거나 짝이면 true
```

## 4. 재 본 것

서비스 판정이 있는 실제 고민 1,244건(11/9~14)의 세부 일치율이에요. 서비스 판정은 그때 값 그대로예요.

| | 일치 | 비율 |
|---|---|---|
| 고치기 전 | 876 | 70.4% |
| 정답 5건을 CSO 판정대로 고침 | 880 | 70.7% |
| 같은 값 짝까지 인정 | 906 | 72.8% |

**v4.14와 새 정의로 판별을 다시 돌린 정확도는 재 보지 않았어요.** 올리기 전에 정답 세트로 v4.12와 비교해 주세요. 특히 바꾼 면접 규칙과 WK-WHEN·LV-LONGSOLO가 다른 글을 틀리게 하지 않는지 봐 주세요.

2. 돈·생활 틀(F39)·진로 틀(F37)을 나눌지, ET-SAFE를 운세 틀로 옮길지.

## 6. v2.3.23에서 더 바꾼 것 (CSO 11/15)

- 대학 입시 면접도 면접 세부(JB-INTERVIEW)로 보내요. 프롬프트 v4.15, 세부 정의 v6.
- JB-INTERVIEW가 속한 틀(F30)의 이름은 '취업 · 될지·시작할지 (코앞)'이에요. 입시·대학원 면접 글에 취업 쪽 말(회사·채용)이 나오지 않는지 F30의 전용 문장과 장면 문장을 확인해야 해요. 확인 전이에요.

## 7. v2.3.24에서 더 바꾼 것 (CSO 11/15)

프롬프트 v4.16, 세부 정의 v7, 정답 예시 `frame_gold_v2.10.jsonl`.

| 바꾼 것 | 내용 |
|---|---|
| 두 고민 | 먼저 쓴 쪽이 아니라 **더 무거운 쪽**. "연애도 결혼도 못 할 것 같다" → 결혼(MR-WHEN). 무게를 못 가릴 때만 먼저 쓴 쪽 |
| 새 세부 SB-FLOW | '지금 하는 일이 잘 풀릴지'. 매출(SB-RUN)도 적성(WK-FIT)도 아닌 글. 틀 F36, 점수표 start. 세부 145개 |
| 답할 수 없는 꼴의 질문 | 말없이 바꿔 읽음. 벌이가 적어 낼 돈을 피할 길을 묻는 글 → SB-FLOW(앞 판의 MN-WHEN에서 바꿈) |
| CR-DISTANCE / CR-CHANCE | 나이 차·거리 같은 사정은 겉으로 든 예. 사귀어도 될지를 물으면 CR-CHANCE. 채점용 짝에서 뺌(9쌍) |
| 가벼운 고민 | 카드 결과를 그대로 둠(규칙 추가 없음) |

- '더 무거운 쪽'을 프롬프트에 풀어 쓴 문장("삶에서 더 크고 오래가는 일이거나 글에서 더 길고 절실하게 쓴 쪽")은 Claude 초안이에요.
- SB-FLOW는 예시 12개를 새로 써서 `frame_gold_v2.10.jsonl`에 넣었어요. 비슷한 예시 검색의 색인을 v2.10으로 다시 만들어야 후보에 나와요.
- SB-FLOW의 1·2쪽 장면 문장은 진로·창작 묶음(PATH)을 써요. 전용 문장은 없어요.
- v4.16으로 다시 돌린 정확도는 재 보지 않았어요.
