# 작심삼일 챌린지 → 쏘웰라 넘김 v1 (2026-11-25)

CSO: "좋아 이거 그리고 꼭 작심삼일 챌린지 자료 쏘웰라로 넘기도록 해줘"

## 흐름
1. 결제 뒤 결과를 만들 때(`buildPagesV4({ challenge: { …, resultId } })`) 9쪽·10쪽에 `pg.handoff`(넘김 묶음)가 붙어요.
2. **서버가 이 묶음을 계정에 저장**해요(버튼을 누르기 전에). 저장 키 = `user_id` + `result_id`. 형식은 `02_데이터/challenge_handoff.schema.json`(`swh.challenge.v1`).
3. 버튼은 `pg.links`의 주소로 가요. 주소에는 `result_id`만 넣고 고민·닉네임은 넣지 않아요.
   - 9쪽 [3일 챌린지 시작하기], 10쪽 [작심삼일 챌린지 시작하기] → `/sowella/challenge?from=tarot&rid=…`
   - 10쪽 [쏘웰라에게 물어보기] → `/sowella/chat?from=tarot&rid=…`
   - 10쪽 [풍등 받으러 가기] → `/sowella/lantern?from=tarot&rid=…` (풍등은 챌린지 처음에 날림)
4. 쏘웰라 갓생러모임은 로그인한 계정에서 `result_id`로 묶음을 읽어 **5칸 계획(1·2·3일차·1주일·1달)을 그대로** 보여 줘요. 위에 "테스트 결과에서 가져왔어요 · {activity.name}" 한 줄(쏘웰라 시안의 fromtheme 줄).
5. 버튼을 누르지 않은 사람도 쏘웰라에 들어오면 첫 화면에 "타로에서 받은 작심삼일 챌린지가 있어요"로 보여 줘요(`status: ready`).

## 상태
| status | 언제 |
|---|---|
| ready | 결과를 만들 때 저장 |
| started | 갓생러모임에서 시작(그날이 1일차) |
| done | 도장 3개 |

- 하루 빠져도 이어서 해요(`rules.skip_ok`). 도장 3개면 끝(`stamps_to_finish`).
- 같은 계정에 여러 결과가 있으면 가장 최근 것을 먼저 보여 주고, 나머지는 목록에 남겨요.
- 인증 사진은 내부 3년 보관(CSO 11/24), 원본째.
- 스토리 카드 글은 `plan[].story`(20자 안).

## 넘기는 것 / 넘기지 않는 것
| 넘김 | 넘기지 않음 |
|---|---|
| 닉네임, 영역·세부·첫 갈래(코드·문장), 2·3번 카드 키, 활동 가족, 짝 줄, 5칸 계획, 풍등 이용권 여부 | 고민 원문, 이메일 |

- 쏘웰라 대화에서 고민 원문이 필요하면 쏘웰라가 같은 계정의 타로 결과를 따로 읽어요(이번 넘김 묶음에는 넣지 않음).

## 사주·점성술도 같은 형식
- `source`만 바꿔(`saju`, `astro`) 같은 형식으로 넘기면 쏘웰라가 한 가지 방식으로 받아요. 사주 v1.6.1의 13쪽 챌린지도 이 형식에 맞추는 것을 제안해요.

## v2 (v3.13 · 2026-11-26)
CSO: "쏘웰라에 1,2,3일차 + 1주일 + 1달 챌린지랑 테스트 결과 전체 + 일상어 고민 넘기는 것까지 꼭 잊지말고 반영해줘.."
- 형식 `swh.challenge.v2`: 위 v1의 "넘기지 않음"에서 **고민 원문을 넘김**으로 바꿈(`worry.text`). **결과 쪽 전체**(`result`)와 **쏘웰라 실천 코드**(`plan[].practice_id`)를 더함. 이메일은 여전히 넘기지 않음.
- 쏘웰라 오늘의 제안 순서(쏘웰라 규칙 DAILY-01: 타로 계획 → 타로 고민 → …)에 그대로 쓰일 수 있음.
