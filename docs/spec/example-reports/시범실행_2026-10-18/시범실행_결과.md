# 쏠 타로 시범 실행 결과 (2026-10-18)

고민 2개를 실제 흐름 그대로 돌렸습니다: 고민 분류(A) → 안전 확인 → 무작위 셔플·뽑기 → 카드별 한 줄·메인 문구(C) → 이야기·내 고민에 대어 보면(D) → 출력 검증 → 8쪽 조립.

- **모델**: 운영 API 키가 없어, 저비용 모델(Claude Haiku)에게 **프롬프트 문서의 시스템 프롬프트와 사용자 입력만** 주고 응답을 받았습니다. 운영에서 쓸 모델과는 다를 수 있습니다.
- **카드**: 실제처럼 무작위로 섞고 뽑았습니다(방향 포함). 고친 뒤 다시 돌릴 때는 비교를 위해 같은 카드를 썼습니다.
- 결과 화면: `live1_swipe-standalone.html`, `live2_swipe-standalone.html` (결제 전/후 전환), 전체 문장: `live1_report.md`, `live2_report.md`

## 잘 된 것
- 분류는 두 번째 시도부터 두 사례 모두 의도대로(오래된 고민·마감·남에게 달림까지) 나왔고, 안전 오탐 없음.
- 결과 AI가 "연락해도 될까요?"에 답하지 않고 "보낼지 말지는 지윤님이 정할 일이고, 그 전에 이 마음이 바람인지 두려움인지 천천히 나눠 보는 것도 하나의 방법이에요"처럼 되묻기 방향을 그대로 살림.
- 카드 비유(펭귄·해달·물개 / 백조·왜가리·개구리)를 고민 장면에 붙여 씀. 예언·단정 표현 없음.

## 아직 남은 것
- 2건뿐이고, 고친 프롬프트로 **한 번씩만** 다시 돌렸습니다. 판별 DB 평가 세트(2,012문항)와 영역별 리포트 3~4건씩은 운영 모델로 돌려야 합니다.
- 1번 사례 '해결을 늦추는 건 쉬지 못하는 마음'(두 번째 카드 해달 역방향의 결)은 이야기 문단의 해석("남을 품느라 비어 있음")과 결이 조금 다릅니다. 카드 결 하나로 정하는 고정 문장의 한계라, 상담사 검수 때 걸림돌 문장 12개를 함께 봐 주세요.
- 건당 비용·대기 시간은 이 방식으로는 잴 수 없습니다.
