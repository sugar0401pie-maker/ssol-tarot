## 1. 개요

**한 줄 요약**: 사용자가 고민을 짧게 적으면 AI가 고민의 영역·감정·필요를 읽습니다. 사용자는 고민을 떠올리며 카드를 섞고, 펼쳐진 22장 중 마음 가는 3장을 직접 뽑아 **지금의 마음 / 나를 붙잡는 것 / 다음 한 걸음**을 보고, 웰니스 실천 제안을 받습니다. 카드는 미래를 맞히는 도구가 아니라 고민을 다른 각도로 비추는 거울입니다.

| 그대로 쓰는 것 (디저트·관계성 테스트) | 새로 만든 것 |
|---|---|
| 인트로 → 온보딩 → 본 테스트 → 결과 → 유료 리포트 → 공유 → 계정 저장 흐름 | 환영·닉네임·타로 경험 질문, 고민 자유 입력(건너뛰기 가능) + 백그라운드 AI 분류(영역 6 × 감정 8 × 필요 6) |
| 카카오·네이버·이메일 가입, 토스 결제(이 테스트는 **1,900원 리포트만**, 7.5) | 카드 22장(메이저 아르카나 구조 + 쏠 바다 캐릭터 + 웰니스 재해석) |
| 조사 자동 처리 함수, 결과 하단 고지문 | 22장 무작위 셔플(다시 섞기 가능) + 사용자가 직접 3장 + 위치 배정 |
| **결과 페이지 블러 페이월**(관계성 테스트와 동일) | 카드 셔플·펼침·선택·뒤집기 애니메이션 |
| 공유 시트 6종, 계정 단위 위기 신호 이력 | 3단계 안전 확인(서버 키워드 + AI) |
| 리포트 파이프라인: 서버 조립 + gpt-6-sol 생성 + 자동 검증 + 1회 재생성 | 8섹션 타로 리포트, 예언 금지 규칙 |
| **로고 색감(남색·크림)** 디자인 토큰 — 관계성 테스트 7장 | 카드 앞·뒷면 규격, 카드 이미지 22+1장 |

**포지셔닝**: 운세·점술이 아니라 전문 심리상담사가 만든 자기이해 웰니스 콘텐츠입니다. "예언", "운명", "맞힌다" 같은 표현은 화면·광고 어디에도 쓰지 않습니다.

## 2. 전체 사용자 플로우

```
[인트로] 디저트 테스트와 동일(히어로 + 참여자 수 + "테스트 하기")
   → [환영] "쏠 타로 하우스에 오신 당신을 환영합니다." / "당신을 뭐라고 불러드리면 될까요?"
        닉네임 입력 → [이렇게 불러주세요]
   → [경험] "{닉네임}님, 오늘은 어떤 고민을 가져오셨나요?" / "타로카드는 처음이신지요?"
        ├─ [전에 본 적이 있어요] ──────────────────────────────┐
        └─ [네, 처음이에요] → [처음 안내] "오늘 {닉네임}님의 고민을 타로카드가…" → [네, 좋아요!] ┘
   → [고민 쓰기] "좋습니다. 먼저 {닉네임}님의 고민을 편하게 작성해주세요." / "구체적으로 쓸수록…"
        ├─ [제출하기] → (서버) 안전 키워드 즉시 확인
        │        ├─ urgent → [안전 안내 화면] (카드 진행 중단)
        │        └─ 그 외 → 셔플로. AI 고민 분류는 셔플 연출 동안 백그라운드
        │                   (도중에 AI가 urgent를 주면 그 자리에서 안전 안내로 전환)
        └─ [고민은 마음속으로만 생각하고 싶어요] → 바로 셔플로 (고민 미작성 모드: 분류·연결 한 줄 없음)
   → [셔플] "이제 카드를 선택할 시간입니다…" 안내 + 카드 섞이는 연출
   → "카드가 잘 섞였습니다. 원하신다면 다시 섞으셔도 돼요."
        ├─ [다시 섞을게요] → (서버) 새로 무작위 셔플 → 같은 화면 반복
        └─ [지금 뽑을게요]
   → [뽑기] 22장 펼침, "고민을 되새기면서 가장 마음이 가는 카드 3개를 뽑아주세요."
        카드를 누르는 즉시 뒷면→앞면 뒤집기, 위쪽 슬롯(지금의 마음/나를 붙잡는 것/다음 한 걸음)으로 이동
        3장째를 뽑는 순간 → (서버, 백그라운드) 무료 결과 조립 + 카드별 고민 연결 한 줄 생성 시작
   → "카드를 다 뽑았어요. 이제 설명을 보러 가볼까요?" [네, 좋습니다.]
        준비가 끝났으면 바로, 아니면 "{닉네임}님의 타로 결과를 분석하고 있어요... (n초 경과)"
   → [결과 페이지 한 스크롤]
        1·2번 무료 → 3번 앞 2줄 무료 → 블러 + 결제 카드 + 하단 고정 바
        ├→ 결제 → "리포트 쓰는 중" → 같은 자리에서 블러 해제, 3~8번 표시
        ├→ [내 카드 공유하기] (공유 시트 6종)
        ├→ [결과 저장하기] (계정 만들기)
        └→ [다른 고민으로 다시 해 보기]
```

## 3. 분류 체계

고민을 세 가지 축으로 읽습니다. 코드값과 문구는 `tarot_data.json`의 `domains`, `emotions`, `needs`.

**영역 (하나)** — 고민의 무대. 디저트 테스트(쏠 웰니스 유형 진단)에서 확정한 **생활 영역 태그 6개**를 그대로 씁니다.

| 코드 | 이름 | 들어가는 고민 | 경계 규칙 |
|---|---|---|---|
| CAR | 직업·커리어 | 직장, 업무, 상사·동료, 성과, 이직, 번아웃, 일과 삶의 균형 | 직장 안 관계·이직은 여기. 일과 삶의 균형도 여기(디저트 결정) |
| DIR | 진로·자기계발 | 앞으로의 길, 전공·취업 준비, 시험·자격증, 공부 + **나 자신·삶의 방향**(삶의 의미, 자존감·자기 평가, 감정 기복·마음 컨디션) | 직장 전 취업 준비는 여기. 나 자신·삶의 방향 쪽은 `self_focus=true`, 결과 문장은 "나 자신과 삶의 방향에 대한 고민" |
| LOV | 연애 | 연인, 썸, 고백, 이별, 소개팅, 결혼을 앞둔 관계 | 배우자 본인과의 고민은 여기, 배우자의 가족은 가족 |
| FAM | 가족 | 부모, 형제자매, 자녀·양육, 배우자의 가족, 간병, 독립 | 가족의 돈 문제도 관계·부담이 중심이면 여기 |
| SOC | 교우·사회관계 | 친구, 모임, 단톡방, 동호회, 이웃, 부탁과 거절, 소외감 | 이사 후 외로움처럼 관계가 중심이면 여기 |
| LIF | 재정·생활안정 | 돈, 저축·대출·소비, 주거·이사, 생활비, 생활 리듬, 수면·운동 습관 | 감정 기복·마음 컨디션은 여기가 아니라 진로·자기계발 |

- 여러 영역이 섞이면 **감정이 가장 크게 걸린 쪽**을 고릅니다.
- 6개 영역에 '나 자신'이 따로 없어서, **나 자신은 삶의 방향과 함께 진로·자기계발에 묶습니다**(v1.5 결정). 자존감·감정 기복·삶의 의미 같은 고민은 `self_focus=true`로 표시하고, 결과 첫 문장은 "나 자신과 삶의 방향에 대한 고민으로 읽혔어요"로 나갑니다. 리포트 AI는 이 표시가 있으면 취업·공부 장면으로 좁히지 않습니다.
- 영역별 예시 문장과 경계 사례 60개: `worry-examples.md`(상담사 검수 후 정답 확정).

**감정 (1~2개, 큰 순서)** — 불안(ANX) · 지침(TIR) · 외로움(LON) · 서운함(HUR) · 막막함(CON) · 자책(SHA) · 슬픔(GRI) · 설렘(HOP)

**필요 (하나)** — 지금 가장 바라는 것: 쉼(REST) · 시작할 용기(START) · 정리와 선택(CHOOSE) · 연결(CONNECT) · 나를 지키는 선(BOUNDARY) · 놓아주기와 회복(LETGO)

**위치 (3)** — 사용자가 고른 순서대로: ① 지금의 마음 ② 나를 붙잡는 것 ③ 다음 한 걸음

> 디저트 테스트와 같은 생활 영역 6개를 쓰므로, 나중에 디저트 결과·쏘웰라 상담 기록과 같은 기준으로 묶어 볼 수 있습니다.

## 4. 카드 덱 — 22장

메이저 아르카나 22장의 **구조와 원 카드의 결**만 빌리고, 이름·그림·해석은 웰니스식으로 새로 만들었습니다. 캐릭터는 관계성 테스트의 쏠 캐릭터 20종 + 히든 '바다의 노인' + 단체 카드 1장입니다. 카드 의미는 캐릭터가 관계성 테스트에서 가진 성격(역량 × 방식)과 어긋나지 않게 배정했습니다.

| # | 원 카드 | 웰니스 카드명 | 캐릭터 (관계성 테스트 위치) | 핵심 메시지 |

| 0 | 바보 | 첫 물장구 | 수달 (기대기·다가가기) | 서툴러도 시작해도 괜찮아요 |
| 1 | 마법사 | 여덟 갈래의 손 | 문어 (회복하기·다가가기) | 이미 가진 자원을 써 봐요 |
| 2 | 여사제 | 고요히 바라보기 | 왜가리 (믿기·거리두기) | 내 직감에 귀 기울이기 |
| 3 | 여황제 | 품어 주는 품 | 해달 (기대기·맞춰주기) | 나를 돌보고 채우기 |

**역방향을 씁니다(v1.8, 5.5).** "거꾸로 = 나쁨"이 아니라 "그 힘이 아직 안쪽에 머무는 상태"로 해석합니다.

## 5. 카드 뽑기 알고리즘 (v1.1)

### 5.1 사람이 읽는 버전

1. 사용자가 셔플 화면에 들어오면 서버가 22장 순서를 **무작위로 섞고**(crypto 난수, Fisher–Yates) `shuffleId`를 발급합니다.
2. "다시 섞을게요"를 누를 때마다 서버가 **새로 섞고** 새 `shuffleId`를 줍니다. 횟수 제한은 없고, 몇 번 섞었는지 기록합니다.
3. 화면에는 **뒷면 22장(자리 번호 0~21)만** 보냅니다. 어느 자리에 어떤 카드가 있는지는 서버만 압니다.
4. 사용자가 자리를 누르면 서버가 그 자리의 카드를 알려 주고, 화면은 즉시 앞면으로 뒤집습니다.
5. 뽑은 순서 = 위치: 1장째 지금의 마음, 2장째 나를 붙잡는 것, 3장째 다음 한 걸음. 한 번 뒤집은 카드는 되돌리지 않습니다(실제 타로처럼).
6. 카드의 의미는 고민과 상관없이 카드 자체에 정해져 있고, 고민과의 연결은 해석 단계(AI)가 맡습니다 — 해석 구조는 5.3.

### 5.2 원칙

- 쏠 테스트의 "무작위 금지"는 점수로 유형을 정하는 테스트에 대한 원칙입니다. 이 테스트는 **사용자가 직접 뽑는 것 자체가 경험의 핵심**이라, 카드 순서만 무작위로 섞고 결과는 사용자의 선택으로 정해집니다. 화면 안내도 이 사실과 어긋나지 않게("고민과 닮은 카드가 찾아왔다" 같은 표현은 쓰지 않음) 썼습니다.
- 셔플마다 `shuffleId`·카드 순서·뽑은 자리를 저장해 결과를 재현하고 확인할 수 있게 합니다.
- 이전 버전의 "고민 맞춤 7장"(`selectCards.js`의 `shortlist`)은 **보류 모드**로 코드와 테스트를 남겨 뒀습니다. 나중에 "추천 카드 보기"나 A/B 테스트에 쓸 수 있습니다.

### 5.3 해석은 어떻게 만들어지나 (3층 구조)

| 층 | 무엇 | 누가 | 어디에 보이나 |
|---|---|---|---|
| ① 카드 고정 해석 | 카드 22장 × 위치 3개 = **66개 해석**, 카드별 핵심 메시지·키워드·실천 3개·이론 | 상담사 검수 데이터(`tarot_data.json`) | 무료 1·2번 |
| ② 고민 읽기 | 고민 원문 → 영역·감정·필요 분류(사용자 확인) | 저비용 AI + 사용자 | 무료 2번 첫 문장 |
| ③ 고민 × 카드 엮기 | (무료) 카드별 고민 연결 한 줄 / (유료) 세 장의 흐름, 마음 깊이 읽기, 처방, 실천 카드 | AI가 ①의 데이터만 재료로, 정해진 규칙 안에서 작성 | 무료 2번 / 유료 3~7번 |

- 같은 카드라도 **위치에 따라 다른 해석**이 나옵니다. 예: '부풀어 오른 마음(복어)'은 지금의 마음 자리에선 "상처받지 않으려 부풀어 있는 마음", 나를 붙잡는 것 자리에선 "불안할 때 반복하는 습관", 다음 한 걸음 자리에선 "부풀어 오르는 순간을 알아차리기".
- AI는 카드 데이터에 없는 의미를 새로 만들지 않고, ①의 해석·실천·이론을 이 사람의 고민 장면에 붙이는 역할만 합니다. 예언·진단·관계 판단은 프롬프트와 자동 검증으로 막습니다.

### 5.5 역방향 (v1.8)

- **정하는 법**: 셔플할 때 서버가 카드마다 **50% 확률**(`deck.reversed_rate`, crypto 난수, 전통 타로와 같음)로 역방향을 정합니다. 값만 바꾸면 조정됩니다. 카드 뒷면(달 물결)이 위아래 대칭이라 뽑기 전에는 방향을 알 수 없습니다.
- **해석 원칙**: 역방향은 "나쁜 카드"가 아니라 그 카드의 힘이 **아직 안쪽에 머물러 있거나(막힘) 한쪽으로 지나치게 쓰이는(과함)** 상태입니다. '부풀어 오른 마음'(악마)·'달빛 아래 떠다니기'(달)처럼 전통적으로 역방향이 "풀려남·걷힘"인 카드는 그 뜻을 따릅니다. 카드마다 역방향 핵심 메시지 1개 + 위치별 해석 3개(`cards[].reversed`).
- **화면**: 뒤집을 때 카드 그림이 180도 돌아간 채 나오고, 카드명은 그림 아래에 바로 선 글자 + 작은 "역방향" 표시. 결과 화면의 카드 썸네일도 같은 방식.
- **AI**: 연결 한 줄·이야기 문단 입력에 방향을 함께 넘기고, 역방향을 "나쁘다·불길하다"로 표현하지 않게 합니다.
- **안내**: 처음 안내나 결과 1번 아래에 작은 글씨로 "역방향은 그 카드의 힘이 아직 안쪽에 머물러 있다는 뜻이에요"를 한 번 보여 줍니다.

### 5.4 코드와 검증

- `03_코드/deck.js`: `shuffleDeck()`, `createShuffle()`, `pickSlot()`, `picksFromSlots()`, `loadingText()`
- `03_코드/test_tarot.mjs`: 셔플이 22장을 빠짐없이 쓰는지, 다시 섞을 때마다 순서가 바뀌는지, 22,000회 셔플에서 첫 자리 분포가 고른지, 뽑은 순서대로 위치가 정해지고 중복·4장째가 거부되는지 등 **20개 테스트 통과**

## 6. 안전 확인

자유 입력이라 위기 신호가 들어올 수 있습니다. 지식베이스 공통 규칙(위기 신호 시 임상 연계, D19)과 디저트 운영 결정(계정 단위 위기 신호 이력 저장)을 그대로 따릅니다.

| 단계 | 판단 | 화면 처리 |
|---|---|---|
| urgent | 죽고 싶다·자해·삶을 끝내는 생각이 직간접적으로 드러남 | 카드 진행 **중단**. 안전 안내 화면(109 자살예방상담전화, 1577-0199, 119/112 [번호 출시 전 확인]) + 쏠 전문 상담 안내. 결제 유도 없음 |
| watch | 극심한 무기력·절망·불면·고립감 | 진행은 하되 결과 8번에 안내 박스, AI 리포트는 가장 부드러운 실천만. 계정이 있으면 위기 신호 이력 저장 |
| none | 그 외 | 일반 진행 |
| violence | 폭력·협박·통제·스토킹·상대가 무서움 | 진행하되 **상대에게 다가가는 실천(approach) 제외**, 8번에 1366·112 안내, 관계 판단 금지 |

**판단 방법 — 두 겹**

1. **서버 키워드 확인(즉시)**: 제출하는 순간 `safety.js`가 문장에서 키워드를 찾습니다. 대부분은 띄어쓰기를 지운 뒤 찾고("죽고 싶"·"죽고싶" 모두 잡기 위해), '자살'·'자해'처럼 두 글자 단어는 원문 그대로에서 찾습니다("혼자 살기"가 '자살'로 잡히는 오탐 방지).
   - urgent: 죽고 싶 / 죽어 버리 / 자살 / 극단적 선택 / 사라지고 싶 / 살기 싫 / 살고 싶지 않 / 자해 / 유서 / 뛰어내리 / 목숨을 끊 / 삶을·인생을 끝내 / 세상을 떠나고 싶 / 없어지고 싶
   - watch: 너무 힘들 / 버틸 수가 없 / 버티기 힘들 / 아무 의미 없 / 아무것도 못 하겠 / 숨이 막 / 무기력 / 잠을 못 자 / 매일 울 / 혼자인 것 같 / 아무도 없 / 지쳐서 아무것도
   - violence: 때리·때렸 / 맞았 / 폭력·폭행 / 협박·위협 / 감시 / 휴대폰·핸드폰을 검사 / 폰을 뒤 / 위치 공유 강요 / 못 만나게 / 물건을 던지 / 스토킹 / 따라다니 / 무서워서
2. **AI 판단(셔플 동안)**: 고민 분류 AI가 같은 기준(A-2 프롬프트)으로 표현을 바꿔 쓴 문장까지 판단합니다. 예: "다 끝내 버리면 편해질 것 같아요"는 키워드에 없지만 AI가 urgent로 잡아야 합니다.

- 두 결과 중 **항상 높은 쪽**을 따릅니다(`mergeSafety`).
- 키워드는 넓게 잡으면 오탐, 좁게 잡으면 미탐이 생깁니다. "관계를 끝내고 싶어요", "배고파 죽겠어요"는 위기가 아니라서 키워드에서 뺐고, "숨이 막혀요" 같은 관용 표현은 watch로 걸리지만 결과에 안내 박스만 붙고 진행은 그대로입니다. 이런 경계 사례는 `worry-examples.md`의 SAFE-01~06에 정리했고 테스트로 확인합니다.
- 서버 키워드 확인(`safety.js`의 `screenText`)과 AI 분류의 `crisis_level`·`violence`를 합칠 때는 **항상 높은 쪽**을 따릅니다(`mergeSafety`).
- 키워드 목록은 보조 장치라 오탐·미탐이 있습니다. 파일럿 데이터를 상담사와 함께 검토해 보완합니다.
- 공유 카드·리포트 어디에도 고민 원문과 안전 판단 결과를 노출하지 않습니다.

### 7.1 환영 · 닉네임

- 큰 글씨: "쏠 타로 하우스에 오신 당신을 환영합니다." / 작은 글씨: "당신을 뭐라고 불러드리면 될까요?"
- 닉네임 1~10자. 비어 있으면 버튼을 눌렀을 때 인라인 안내 "불러드릴 이름을 적어 주세요."
- 버튼: [이렇게 불러주세요]. 이후 모든 화면·결과·대기 안내에서 "{닉네임}님"으로 부릅니다(호칭 없음).

### 7.2 경험 질문 · 처음 안내

- 큰 글씨: "{닉네임}님, 오늘은 어떤 고민을 가져오셨나요?" / 이어서 "타로카드는 처음이신지요?"
- [전에 본 적이 있어요] → 바로 고민 쓰기.
- [네, 처음이에요] → 처음 안내 화면: "오늘 {닉네임}님의 고민을 타로카드가 어떻게 비춰 주는지 들어봅시다. 우리 쏠 하우스만의 특제 레시피로 {닉네임}님의 타로 카드가 설명하는 현재 상황에 적절한 웰니스 제안을 해드릴게요. 이제 한 번 해볼까요?" → [네, 좋아요!] → 고민 쓰기.
- 선택값(`returning` / `first`)은 세션에 저장해 이탈률·전환율 분석에 씁니다.

### 7.3 고민 쓰기

- 제목: "좋습니다. 먼저 {닉네임}님의 고민을 편하게 작성해주세요." / 안내: "구체적으로 쓸수록 도움이 됩니다. 고민을 굳이 작성하지 않으셔도 타로카드는 볼 수 있어요."
- 입력란 10~300자(글자 수 표시), 예시 문장 3개 순환 placeholder.
- [제출하기]: 10자 미만이면 인라인 안내. 제출 즉시 서버가 안전 키워드를 확인하고(urgent면 안전 안내), 아니면 셔플로 넘어갑니다. **AI 고민 분류는 셔플 연출(최소 3초) 동안 백그라운드로** 돌리고, 확인 화면은 두지 않습니다. 셔플·뽑기 도중 AI가 urgent를 돌려주면 그 자리에서 안전 안내로 전환합니다.
- [고민은 마음속으로만 생각하고 싶어요]: 고민 없이 바로 셔플로. **고민 미작성 모드** — 분류·카드별 연결 한 줄을 만들지 않고, 결과 2번 첫 문장과 3번 앞 2줄은 미작성용 문장으로, 유료 리포트는 프롬프트 B의 미작성 규칙으로 씁니다(`assembleReport.js`가 `cls=null`을 처리).
- 하단 작은 글씨 고지(디저트 온보딩 안내 불릿을 옮긴 것): 자기이해 웰니스 콘텐츠이며 예언·진단·치료가 아님 / 고민은 해석에만 쓰이고 공유 카드에 안 보임.
- 디저트 온보딩의 "로그인 없이 시작" 안내는 결과 화면 저장 버튼 근처로 옮깁니다.

**뽑기 화면**

| 요소 | 내용 |
|---|---|
| 안내 | "고민을 되새기면서 가장 마음이 가는 카드 3개를 뽑아주세요." |
| 슬롯 | 위쪽에 빈 슬롯 3개: ① 지금의 마음 ② 나를 붙잡는 것 ③ 다음 한 걸음 + "0 / 3" |
| 카드 배치 | **22장을 한 화면에 모두** 보여 줍니다. 모바일(375px)은 **두 줄 부채꼴(위 11장·아래 11장)**, 카드 폭 약 52px·겹침. 손가락을 대고 훑으면 닿은 카드가 살짝 떠오르고, 떼는 순간 그 카드가 선택됩니다(작은 카드를 정확히 누르기 어려운 문제 해결). 태블릿·데스크톱은 한 줄 부채꼴 22장 |

| 3장째 | 나머지 19장이 흐려지며 사라지고, 3장이 가운데 크게 나란히 정렬 → "카드를 다 뽑았어요. 이제 설명을 보러 가볼까요?" + [네, 좋습니다.] |

- 뽑기 중 다른 카드를 연달아 눌러도 애니메이션이 끝날 때까지 다음 입력은 받지 않습니다(중복 선택 방지).
- 앞면 이미지는 서버가 그 자리의 카드를 알려 준 직후에 불러옵니다. 뒤집는 0.6초 동안 이미지가 준비되도록 회전 전반부(0~90도)에 로드하고, 늦으면 90도에서 잠깐 멈췄다가 넘깁니다. 이미지가 없으면 카드명이 적힌 대체 카드.
- 구현: CSS 3D transform(`perspective`, `backface-visibility: hidden`) + Framer Motion(또는 motion). 별도 게임 엔진 불필요.
- `prefers-reduced-motion`이면 셔플·회전 대신 페이드로 대체(셔플 최소 시간 3초는 유지).
- 진동(`navigator.vibrate(10)`)은 지원 기기에서만, 선택 사항.

### 7.6 대기 안내 (모든 대기 화면 공통, v1.1)

- 문구: **"{닉네임}님의 타로 결과를 분석하고 있어요... (n초 경과)"** — 경과 초는 1초마다 갱신(`deck.js`의 `loadingText`, `tarot_data.json` → `copy.loading`).
- 쓰는 곳: "네, 좋습니다." 후 결과 준비가 덜 됐을 때, 결제 후 리포트 생성, 공유 이미지 생성. 바로 끝나는 경우(0.5초 미만)에는 띄우지 않습니다.
- 물결 심볼 로딩 애니메이션과 함께 표시.
- **일정 시간 이상 걸릴 때의 추가 안내는 미정**입니다(CSO 결정 예정). 코드에는 `onLongWait(seconds)` 자리만 만들어 두세요.
- 닉네임은 환영 화면에서 받습니다.

### 7.7 백그라운드 결과 준비와 API 순서 (v1.1)

"네, 좋습니다."를 누르기 전에 결과가 준비돼 있도록, **3장째를 뽑는 순간** 서버가 준비를 시작합니다.

| 순서 | API (제안) | 하는 일 |
|---|---|---|
| 1 | `POST /api/tarot/session` | 닉네임·경험 선택값 저장 |
| 2 | `POST /api/tarot/session/:id/worry` `{text}` 또는 `{skip: true}` | 고민 저장, 안전 키워드 즉시 확인(urgent면 안전 안내). 그 외에는 즉시 응답하고 AI 분류를 백그라운드로 시작. 클라이언트는 셔플·뽑기 중 `GET …/status`로 urgent 여부만 확인 |
| 3 | `POST /api/tarot/session/:id/shuffle` | 새 셔플 생성 → `{shuffleId, count: 22}`만 반환(카드 순서는 안 보냄). 다시 섞을 때마다 호출 |
| 4 | `POST /api/tarot/session/:id/pick` `{shuffleId, slot}` | 그 자리의 카드·위치 반환. **3장째면 응답과 동시에 백그라운드 작업 시작**: ① 무료 1·2번·3번 앞 2줄 조립 ② 카드별 고민 연결 한 줄 AI 호출(최대 12초, 실패 시 생략) |
| 5 | `GET /api/tarot/session/:id/result` | `{status: "preparing" | "ready", free}` — "네, 좋습니다." 후 준비 중이면 대기 안내를 띄우고 1초 간격으로 확인 |
| 6 | 결제 후 `POST /api/tarot/session/:id/report` | 심층 리포트 생성(백그라운드) → 같은 대기 안내 → 저장본 표시 |

- 사용자가 3장째 카드를 보고 "네, 좋습니다."를 누르기까지 보통 몇 초가 걸리므로, 대부분은 대기 화면 없이 바로 결과가 나옵니다.
- **유료 리포트는 미리 만들지 않습니다.** 결제하지 않는 사용자에게도 건당 AI 비용이 생기기 때문입니다.

### 7.8 공유 카드

- 들어가는 것: 세 장의 카드 그림, 카드명, 위치 이름, "{이름}님의 웰니스 타로 세 장", "나도 카드 뽑기" 버튼.
- **들어가지 않는 것: 고민 원문, 감정·필요 분류, 해석 문장, 안전 판단.** 고민은 가장 사적인 정보라 공유 카드에서 완전히 뺍니다.
- 이미지 비율은 인스타 스토리(1080×1920)와 카카오 미리보기(800×400) 두 가지로 만듭니다.

### 7.9 다시 해 보기

- 결과 화면에서는 "다른 고민으로 다시 해 보기"를 제공합니다(고민 쓰기부터 다시). 같은 결과에서 카드만 다시 뽑는 기능은 넣지 않습니다(마음에 드는 카드가 나올 때까지 반복하는 것을 막기 위해). 카드를 뽑기 전 "다시 섞을게요"는 자유롭게 할 수 있습니다.

## 8. AI 연동

| 호출 | 시점 | 모델 | 출력 | 실패 처리 |
|---|---|---|---|---|
| 고민 분류 | 고민 제출 직후, 셔플 동안 백그라운드(무료). 건너뛰면 호출 안 함 | 저비용 모델 [확인필요] | JSON(영역·감정·필요·crisis_level·violence·off_topic) | 1회 재시도 → 실패하면 미작성 모드처럼 해석 |
| 고민 연결 한 줄 (v1.1) | 3장째를 뽑는 순간 백그라운드(무료) | 저비용 모델 [확인필요] | JSON `{now, hold, step}` 각 15~90자 | `parseLinks` 실패 시 1회 재시도 → 12초 초과·재실패면 생략 |
| 심층 리포트 | 결제 확인 후 백그라운드 | `gpt-6-sol`, Responses API, effort low | 3번 본문~7번 마크다운 | `validateReport.js` 실패 시 1회 재생성 → 그래도 실패면 저장 안 함 + 운영 알림 |

- 프롬프트 전문과 운영 설정: `ai-prompts-tarot-v2.md`.
- 고정 시스템 프롬프트를 앞에, `<style_example>`과 `<user_data>`를 뒤에 두어 자동 캐시를 살립니다(디저트 8.5와 같은 원칙).
- API 키는 서버에서만 다룹니다.
- **타로 전용 규칙**: 예언 금지(반드시·운명·~하게 될 거예요), 고민 원문 인용 1~2회·20자 이내, 원문에 없는 사실 지어내지 않기, 상대 판정·관계 지속/종료 권유 금지, 카드 "주의" 준수.
- 자동 검증 항목(`validateReport.js`): 헤더 3~7번·제목 / 분량 2,200~3,500자(프롬프트 목표 2,300~3,300자) / 금지 표현(예언·진단·관계 지시·**) / 학자 이름·영어 미사용 / 6번 처방 • 3개 / 7번 • 오늘·3일 안에·이번 주 / 문단 5문장 이하 / 어미 균형 / 폭력 신호 시 다가가기 표현 없음.
- 쏘웰라 연결: 8번 안내로 쏘웰라(가입 시 3일 무료)에 들어온 사용자의 채팅 첫 컨텍스트에 세 장의 카드명·위치·분류값·리포트 요약을 넘깁니다(고민 원문 전달 여부는 개인정보 검토 후 결정 [확인필요]).

## 11. 개발 시 반드시 알아야 할 유의사항

1. **셔플은 서버에서만 하세요.** 카드 순서를 클라이언트로 보내지 말고, 사용자가 누른 자리 번호만 받아 서버가 카드를 알려 줍니다. 난수는 `crypto`를 쓰고 셔플 기록을 저장합니다.
2. **"예언", "운명", "맞힌다"를 화면·광고·메타 태그 어디에도 쓰지 마세요.** 이 테스트는 자기이해 웰니스 콘텐츠입니다.
3. **안전 판단은 항상 높은 쪽을 따릅니다.** urgent면 카드로 넘어가지 않습니다. 결제 화면도 보이지 않습니다.
4. **고민 원문은 공유 카드·URL·로그·분석 도구 이벤트에 넣지 마세요.** 서버 저장 시 암호화를 권장합니다.
5. **결제 전 유료 본문을 클라이언트로 보내지 마세요.** 블러는 CSS로 가리는 게 아니라 데이터가 없는 상태여야 합니다.
6. **조사는 `josa.js`로만 처리하세요.** 이번 패키지의 `josa.js`는 디저트 7.2 코드에 **ㄹ받침 "로" 규칙**을 더했습니다(예: "다시 빛나는 별로", "2.1로"). 디저트 원본 코드는 "1·7·8"로 끝나는 숫자와 ㄹ받침 단어 뒤에 "으로"를 붙이므로, 디저트·관계성 테스트 쪽도 같은 수정이 필요한지 확인하세요.
7. **카드 해석·실천 문구는 상담사 검수 전 초안입니다.** 검수 후에는 문구를 임의로 다듬지 마세요(디저트 문항과 같은 원칙).
8. **폭력·통제 신호가 있으면 `filterPractices()`로 다가가기 실천을 빼고** AI 입력에서도 제외합니다.
9. **'새 집으로 이사'(원 카드: 죽음)는 전환으로만 해석합니다.** 생명·죽음 관련 표현 금지.
10. 애니메이션은 `prefers-reduced-motion`을 존중하고, 이미지가 없을 때도 크래시 없이 대체 카드로 동작해야 합니다.

## 12. 완료 체크리스트

- [ ] 고민 10자 미만 제출 불가, 300자 제한
- [ ] 서버 키워드 확인 + AI 분류를 합쳐 높은 쪽으로 안전 단계가 정해진다
- [ ] urgent에서 카드·결제 화면으로 넘어가지 않고 안전 안내 화면이 뜬다
- [ ] 인트로가 디저트 테스트와 같은 구성이다
- [ ] 환영 화면에서 닉네임 없이 넘어갈 수 없고, 이후 모든 화면이 "{닉네임}님"으로 부른다
- [ ] "전에 본 적이 있어요"는 바로 고민 쓰기로, "네, 처음이에요"는 처음 안내 → [네, 좋아요!] → 고민 쓰기로 간다
- [ ] "고민은 마음속으로만 생각하고 싶어요"를 누르면 바로 셔플로 가고, 분류·연결 한 줄 AI를 호출하지 않으며 결과가 미작성용 문장으로 조립된다
- [ ] 고민을 제출하면 확인 화면 없이 셔플로 가고, AI 분류가 셔플 동안 백그라운드로 끝난다. 분류 실패 시에도 결과가 끊기지 않는다
- [ ] 셔플·뽑기 도중 AI가 urgent를 주면 안전 안내로 전환된다
- [ ] 화면 이동이 `flow.js`의 규칙과 같다(`test_tarot.mjs` 통과)
- [ ] 셔플 화면 안내문이 섞는 동안 최소 3초 보이고, "지금 뽑을게요" / "다시 섞을게요" 두 버튼이 뜬다
- [ ] "다시 섞을게요"마다 서버가 새로 섞고(새 shuffleId) 같은 화면이 다시 나온다
- [ ] 카드 순서가 클라이언트(네트워크 응답·HTML)에 노출되지 않는다
- [ ] 22장이 모바일 375px 한 화면에 모두 보이고, 훑어서 고르기가 동작한다
- [ ] 누르는 즉시 앞면으로 뒤집히고 슬롯으로 이동한다. 뽑은 순서대로 지금의 마음 / 나를 붙잡는 것 / 다음 한 걸음이 배정되고, 되돌리기는 없다
- [ ] 3장째를 뽑는 순간 백그라운드 결과 준비가 시작되고, "네, 좋습니다." 후 준비 중이면 "{닉네임}님의 타로 결과를 분석하고 있어요... (n초 경과)"가 1초마다 갱신된다
- [ ] 고민 연결 한 줄이 실패하거나 12초를 넘기면 그 줄 없이 결과가 나온다
- [ ] 모든 대기 화면이 같은 대기 안내 컴포넌트를 쓴다(`onLongWait` 자리 포함)
- [ ] 애니메이션이 모바일에서 끊기지 않고, reduced-motion에서 페이드로 대체된다
